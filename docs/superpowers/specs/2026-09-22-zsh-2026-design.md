# zsh 2026: host-aware login path, Starship, and a framework decision

**Status:** approved 2026-09-22; Phase A implemented 2026-09-22; Phase C not started. Phase A plan: `docs/superpowers/plans/2026-09-22-zsh-2026-phase-a.md`
**Branch:** `feat/zsh-2026`, cut from `main` at the squashed audit-remediation commit
**Date:** 2026-09-22

## Why this exists

Two findings drive the whole design. Both were verified on this machine, not assumed.

**Powerlevel10k is the only dead dependency in the login path.** Its author
describes it as on life support; issues and pull requests accumulate without
being worked. Prezto by contrast is slow-moving but alive, with commits as
recent as January 2026. That asymmetry matters: it makes replacing the prompt
urgent and replacing the framework optional.

**Warp does not render the shell prompt, and cannot run most of the
interactive stack.** `WARP_HONOR_PS1=0` is set in every Warp shell on this
machine. Warp draws its own prompt from context chips. Meanwhile the prompt
gate in `runcom/.zpreztorc` asks only `[[ -t 0 ]]`, so inside Warp
Powerlevel10k loads in full, initialises, and every character it produces is
discarded. Five `gitstatusd` processes were running to feed a prompt nothing
displays.

The second finding generalises well beyond the prompt. Warp replaces zsh's
line editor, so anything built on `zle` never fires. Warp's own documentation
lists `zsh-autosuggestions`, `zsh-autocomplete`, `fzf` and `zle-line-init` as
incompatible, documents custom `bindkey` as causing real breakage, and
recommends guarding rc files on `TERM_PROGRAM != "WarpTerminal"`. Roughly half
of this repo's interactive stack is therefore paying startup cost in the
user's primary terminal and delivering nothing.

## Goals

1. Remove Powerlevel10k from the login path and render prompts with Starship,
   which is already installed and already configured in this repo.
2. Load, in each host, only what that host can actually use.
3. Decide deliberately whether to keep Prezto, with evidence rather than taste.
4. Leave the repo's existing guarantees intact: silent startup, exactly one
   compinit, no duplicate or unnormalised PATH entries, a login-shell CPU
   budget, and hermetic side-effect-free tests.

## Non-goals

- Changing the Stow layout, the installer, or anything outside the login path.
- Revisiting mise, which was migrated immediately before this work.
- Preserving Powerlevel10k's exact appearance. The Starship config in this
  repo is the intended look and already mirrors the p10k git vocabulary.
- Making Warp's own UI configurable from this repo. Warp settings are not
  tracked here and will not be.

## Design

### The seam

One classification, computed once, early in the interactive path:

- **Warp** when `TERM_PROGRAM == "WarpTerminal"`. Warp's documented variable,
  and Warp's own recommended guard.
- **Rich terminal** otherwise, when a controlling terminal exists.
- **Dumb** when there is no controlling terminal, which is the existing
  `[[ -t 0 ]]` case and already handled.

Everything zle-dependent moves behind that classification. Nothing else
changes shape.

### What each host loads

| Component | Warp | Rich terminal | Dumb |
|---|---|---|---|
| env, PATH, aliases, functions | yes | yes | yes |
| completions and compinit | yes, provisionally | yes | no |
| zoxide, mise shims, dircolors | yes | yes | yes |
| Prompt | no | Starship | no |
| autosuggestions | no | yes | no |
| syntax highlighting | no | yes | no |
| history-substring-search | no | yes | no |
| fzf keybindings, fzf-tab | no | yes | no |
| atuin ctrl-R widget | no | yes | no |
| custom bindkey | no | yes | no |

The Warp column is not a degradation. Every entry marked "no" is either
documented incompatible or replaced by a native Warp feature.

Completions are marked provisional because Warp consumes shell completions for
some commands, but whether that justifies paying for `compinit` in every Warp
shell has not been measured. See the open questions.

### Phase A: prompt and the seam

Delivered first and revertible on its own.

1. Introduce the host classification.
2. Source `system/.starship` for rich terminals only, ending its orphanhood.
3. Stop loading Powerlevel10k: retire `system/.prompt`, remove the
   instant-prompt block from `runcom/.zshrc`, and set the Prezto prompt theme
   to `off` in every host.
4. Declare `starship` in the `Brewfile`. It is currently installed by hand,
   so a fresh machine would silently lose the prompt.
5. Put the zle-dependent pieces behind the seam.
6. Rework the eight affected assertions in `tests/shell.sh` and add coverage
   for both hosts.

### Phase C: the framework decision

Phase A shrinks Warp's login path to environment only, which narrows this
question to what non-Warp shells need. Phase C is an evaluation, not a
foregone migration.

1. The module accounting is done, and is recorded below. It changes the
   shape of this phase: the cost is concentrated in three modules, and the
   most expensive of them stops running in Warp once Phase A lands.

### Module accounting

| Replacement cost | Modules | Shape |
|---|---|---|
| Trivial: wraps an upstream plugin | `syntax-highlighting`, `autosuggestions`, `history-substring-search`, `prompt` | 18-73 lines each; a `source` plus a few `zstyle` |
| Small: copy options across | `environment`, `history`, `directory`, `terminal`, `spectrum`, `ssh`, `osx`, `git`, `homebrew`, `python` | 20-173 lines each; `setopt`, aliases, a few functions |
| Real work | `editor`, `completion`, `utility` | 457 lines and 50 `bindkey`; 190 lines and 58 completion `zstyle` rules; 270 lines and 84 aliases |

Two consequences follow.

**Antidote is not a replacement for Prezto.** Antidote is a plugin loader;
Prezto is a loader plus a library of configuration. Adopting antidote does not
supply what those 17 modules do. The real choice is between keeping Prezto's
modules under a different loader, which buys little, and leaving Prezto
properly, which means hand-writing the equivalent of `editor`, `completion`
and `utility`.

**Phase A reduces what an exit would buy.** `editor` is entirely zle-based, so
it already does nothing useful in Warp. Once it sits behind the seam, Prezto's
most expensive module stops running in the primary terminal regardless of
which loader is in use. This phase should therefore be re-evaluated after
Phase A, with measurements, rather than decided now.
2. Evaluate antidote, sheldon, and no manager at all against that accounting.
   Zinit is excluded: its turbo mode is discouraged by the author of zsh-bench
   and Powerlevel10k, and this repo values predictability over cleverness.
3. Measure before and after with zsh-bench rather than `time zsh -i -c exit`,
   which does not measure first-prompt lag.
4. Decide, record the decision and its reasoning, and only then implement.

Phase C may conclude that Prezto stays. That is an acceptable outcome and
should not be treated as failure.

## Testing

The existing shell suite is the specification of current behaviour and must
keep passing, except where an assertion encodes something this design
deliberately changes. Those are:

| Test | Why it changes |
|---|---|
| `C0.2` prompt theme off without a terminal | gains a Warp case |
| `C0.3` fzf keybindings only with a terminal | gains a Warp case |
| `C1.6` autosuggest style is not empty | must not run in Warp |
| `C6.1` fzf-tab sourced after prezto | Warp case |
| `C6.2` atuin init is guarded | guard changes |
| `C6.4` ctrl-R reaches atuin | rich-terminal only |
| `C6.5` tab reaches fzf-tab | rich-terminal only |
| `C6.6` key-binding plugins load after prezto | rich-terminal only |

New coverage required:

- A Warp-classified login shell loads no prompt, defines no autosuggest or
  syntax-highlight widget, and still has PATH, aliases, functions, completions
  and zoxide.
- A rich-terminal login shell is unchanged from today except that the prompt
  is Starship.
- Startup stays silent in both, and compinit still runs exactly once in both.
- Every test drives the seam through the environment variable, never by
  detecting the host of the machine running the suite, so the suite is
  deterministic on a CI runner.

## Risks

**A broken `.zshrc` breaks every new shell,** including the ones agent
sessions run in. Mitigation: `zsh -n` after every edit, a login-shell smoke
test after every commit, and small commits that each revert cleanly. This is
already the repo's documented practice.

**The seam could misfire in a host nobody tested,** leaving a terminal with no
prompt or no keybindings. Mitigation: the classification defaults to rich
terminal, so an unrecognised host gets the full stack rather than the reduced
one. Warp is the only special case and it is detected positively.

**Starship may render poorly in some IDE terminals.** Mitigation: verify in
each host the user actually uses before removing p10k, not after.

**Phase C could cost far more than it returns.** Mitigation: it is gated on
the module accounting, and is explicitly allowed to conclude "keep Prezto".

## Success criteria

1. No Powerlevel10k anywhere in the login path, and `starship` declared in the
   Brewfile.
2. A Warp shell loads no prompt and no zle-dependent plugin, and its startup
   is measurably faster than today.
3. A non-Warp shell is functionally unchanged apart from the prompt.
4. Silent startup and exactly one compinit hold in both hosts.
5. The shell suite is green, with the eight changed assertions rewritten to
   assert the new intent rather than deleted.
6. Phase C ends with a written, reasoned decision and zsh-bench numbers
   supporting it.

## Phase A results

CPU per login shell, user plus sys, best of 5 warm runs, real `$HOME`:

| Host | Before | After |
|---|---|---|
| Warp | 270 ms | 190 ms |
| Rich terminal | 260 ms | 210 ms |
| No terminal (agent shell) | 230 ms | 180 ms |

`gitstatusd` processes: 7 before; still 7 at measurement, all belonging to
shells opened before the change. None start in a new shell.

Phase C, the framework decision, starts from these numbers and zsh-bench.

## Decisions taken during review

- `history-substring-search` **stays** in rich terminals. It is not redundant
  with atuin: atuin owns ctrl-R, substring search owns up-arrow.
- Warp shells **keep** `compinit`. Warp consumes shell completions, and the
  cost is accepted without further measurement.
- Warp shells **keep atuin's recording hooks** and lose only its key bindings
  (`--disable-ctrl-r --disable-ai`). The table above covers the ctrl-R widget;
  dropping atuin from Warp entirely would stop commands typed there from
  reaching the shared history. Decided at plan time, after Warp's Command
  Search docs were found to hand ctrl-R to a shell widget when one is bound.
