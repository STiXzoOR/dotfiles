# zsh 2026 Phase A Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Render the prompt with Starship instead of Powerlevel10k, and load in each host (Warp, a rich terminal, no terminal) only what that host can use.

**Architecture:** A new fragment, `system/.term_host`, classifies every interactive shell once, before prezto loads, into `DOTFILES_TERM_HOST` = `warp`, `rich` or `dumb`. `.zpreztorc` drops prezto's four line-editor modules outside rich terminals. `.zshrc` sources Starship, fzf-tab and `.bindings` only in rich terminals. `.fzf` and `.atuin` decide per host themselves. Prezto's prompt theme is `off` everywhere.

**Tech Stack:** zsh 5.9 (login path), bash 3.2 (tests), Prezto (submodule), Starship 1.26, atuin 18.22, BSD `script(1)` for pseudo-terminals in tests.

**Spec:** `docs/superpowers/specs/2026-09-22-zsh-2026-design.md`. Read its "Why this exists" section and the "What each host loads" table before starting.

## Global Constraints

- **Scope is Phase A only.** Phase C (the framework decision) is out of scope and gets its own plan after Phase A ships and is measured.
- **Out of scope (spec non-goals):** the Stow layout, the installer, anything outside the login path, and mise.
- **The login path is live.** `runcom/` and `system/` are stowed into `$HOME`, so every edit reaches every new shell at once, agent shells included. After every edit to a file under `runcom/` or `system/`, run `zsh -n <file>` and `zsh -l -i -c 'exit'`, and fix any failure before doing anything else.
- **Guarantees that must keep holding:** silent startup, exactly one compinit, no duplicate or unnormalised PATH entries, a login shell under 600 ms of CPU (`C6.3`), and hermetic tests with no side effects.
- **The seam defaults to rich.** Warp is the only host detected positively (`TERM_PROGRAM == "WarpTerminal"`). A reader of the class tests `!= (warp|dumb)` for rich-only code, never `== rich`, so a shell in which `.term_host` never ran still gets the full stack.
- **Tests drive the seam through `DOTFILES_TERM_HOST`**, never by detecting the host that runs the suite. The suite runs inside Warp on the author's machine and with no terminal in CI.
- **User decisions, not to be reopened:** migrate off p10k with no speed gate; `history-substring-search` stays in rich terminals; Warp shells keep `compinit`; in Warp, atuin keeps its recording hooks and loses its bindings.
- **Tests are bash 3.2:** no `mapfile`, no `declare -A`, no `${x,,}`, never `((x++))`. A grep-based assertion reads `code_of <file>`, not the raw file, and each new assertion is mutation-checked: break the code, see it fail, restore it.
- **Public repo:** no names, hostnames, emails or absolute `/Users/…` paths in tracked files.
- **Before every commit:** `bash tests/run.sh` and `./bin/dotfiles test` both pass, and `shellcheck -e SC1090,SC1091,SC2034,SC2119,SC2154 -s bash tests/shell.sh tests/lib.sh tests/mise.sh tests/packages.sh` is clean. Do not push.
- **Environment traps:**
  - The Bash tool's shell is zsh with `noclobber`, so overwrite with `>|`.
  - `cp` is aliased to interactive mode, so use `command cp`.
  - Safety Net blocks `git checkout`, so use `git switch`, and restore a file with `git show HEAD:<path> >| <path>`.
  - GitKraken leaves a stale zero-byte `.git/index.lock`. Clear it only when `lsof .git/index.lock` shows no holder.

## Where this plan departs from the spec, and why

1. **No-terminal shells keep compinit.** The spec's table marks compinit "no" for dumb shells, but its Phase A steps never list that change, and removing it would break every `compdef` caller: `system/.completion`, and any `profiles/*.post.zsh` such as gcloud's. `C4.4` would break too. Phase A leaves compinit alone in all three hosts. Measure it in Phase C if it matters.
2. **No terminal wins over Warp.** Checking the terminal first means an agent's `zsh -l -i -c` started from inside Warp is `dumb`, not `warp`, and gets the smallest load. The spec lists the two cases without saying which applies when both hold.
3. **atuin records in Warp.** See the spec's "Decisions taken during review". Warp runs `atuin init zsh --disable-up-arrow --disable-ctrl-r --disable-ai`. `--disable-ai` removes atuin 18.22's binding of `?`, which the other two flags leave in place.
4. **Assertions affected beyond the spec's eight.**
   - `C3.1` (KEYTIMEOUT) now comes from rich terminals only, and passes through the rich pin.
   - `C4.4` (post hook with compdef) is extended to every host in `H0.3`.
   - `tests/mise.sh` `M2.5` orders mise activation after the instant-prompt block. Once that block is gone its check passes without testing anything, so it is rewritten.
   - The prompt checks in `bin/dotfiles-test` and `D1.10` in `tests/packages.sh` change too.
   - `C6.6`, the one spec-listed test left unchanged, still says what it should: the key-binding plugins load after prezto and never from `.profile`. Its rich-only side is covered by `C6.1`, `C6.4` and `H4.3`.
5. **"Exactly one compinit, asserted by a test."** No such test existed. `H0.2` adds it, counting calls with `zsh/zprof`.
6. **The test sandbox stubs starship, fzf, atuin and zoxide by default.** Without that, a sandboxed shell loads whatever the machine running the suite has installed.

# _first_line <pattern> <file> -- the line number of the first line of <file>
# containing <pattern> as a fixed string, or 0 if none does.
#
# Reads through code_of, so an ordering assertion cannot be satisfied by a
# comment that names the thing. code_of blanks rather than deletes, so line
# numbers still line up with the file.
_first_line() {
  code_of "$2" | awk -v p="$1" 'index($0, p) && !n { n = NR } END { print n + 0 }'
}

```bash
# _zsh_login <home> <zsh code> -- the one way this suite starts a sandboxed
# login shell. The host class is pinned rather than detected:
#   ZSHRUN_TERM_HOST  warp | rich | dumb. Default rich, the full stack. Set it
#                     empty to leave the class to system/.term_host.
#   ZSHRUN_ENV        extra NAME=value words, e.g. TERM_PROGRAM=WarpTerminal.
# stdin is /dev/null, so a detected class is never rich.
_zsh_login() {
  # shellcheck disable=SC2086 # ZSHRUN_ENV is a list of NAME=value words
  env -u LC_ALL -u TERM_PROGRAM -u DOTFILES_TERM_HOST \
    HOME="$1" ZDOTDIR="$1" XDG_CACHE_HOME="$1/.cache" PATH="$1/.stubs:$PATH" \
    DOTFILES_TERM_HOST="${ZSHRUN_TERM_HOST-rich}" ${ZSHRUN_ENV:-} \
    zsh -l -i -c "$2" </dev/null
}

# zshrun <zsh code> -- run it in the sandbox, print stdout, discard stderr.
# Set ZSHRUN_HOME to an existing sandbox to reuse it, so that two shells can
# run in sequence against the same caches.
zshrun() {
  local h
  h=${ZSHRUN_HOME:-$(_zsh_sandbox)} || return 1
  _zsh_login "$h" "$1" 2>/dev/null
}

# zshrun_all <zsh code> -- same, but stderr is merged into stdout so that
# startup noise shows up in the result.
zshrun_all() {
  local h
  h=${ZSHRUN_HOME:-$(_zsh_sandbox)} || return 1
  _zsh_login "$h" "$1" 2>&1
}

# ptyrun <command...> -- run it with a pseudo-terminal for stdin, stdout and
# stderr: the only way a test reaches the `[[ -t 0 ]]` branch of
# system/.term_host, since the suite has no terminal of its own in CI. BSD
# script(1) echoes the EOF it forwards as "^D" and ends lines with \r\n; both
# are stripped. stderr arrives mixed into stdout.
ptyrun() {
  /usr/bin/script -q /dev/null "$@" </dev/null | tr -d '\r\b' | sed 's/\^D//g'
}

# pty_zshrun <zsh code> -- a sandboxed login shell on a pseudo-terminal, with
# the class left to system/.term_host. ZSHRUN_ENV says which host it is in.
pty_zshrun() {
  local h
  h=${ZSHRUN_HOME:-$(_zsh_sandbox)} || return 1
  # shellcheck disable=SC2086 # ZSHRUN_ENV is a list of NAME=value words
  ptyrun env -u LC_ALL -u TERM_PROGRAM -u DOTFILES_TERM_HOST \
    HOME="$h" ZDOTDIR="$h" XDG_CACHE_HOME="$h/.cache" PATH="$h/.stubs:$PATH" \
    ${ZSHRUN_ENV:-} zsh -l -i -c "$1"
}

# term_host_of [NAME=value...] -- source system/.term_host in a bare zsh with
# exactly that environment and no terminal; print "class:type", where type is
# scalar, or scalar-export if the class would leak into child shells.
# pty_term_host_of: the same on a pseudo-terminal.
_term_host_code='. "$ROOT/system/.term_host"; print -r -- "OUT=$DOTFILES_TERM_HOST:${(t)DOTFILES_TERM_HOST}"'
term_host_of() {
  env -i PATH=/usr/bin:/bin ROOT="$ROOT_DIR" "$@" zsh -f -c "$_term_host_code" </dev/null |
    sed -n 's/^.*OUT=//p'
}
pty_term_host_of() {
  ptyrun env -i PATH=/usr/bin:/bin ROOT="$ROOT_DIR" "$@" zsh -f -c "$_term_host_code" |
    sed -n 's/^.*OUT=//p'
}
```

# Wall time is useless as a gate on a machine running two dozen agents, so the
# startup budget is measured in CPU (user+sys), which load does not inflate.
login_shell_cpu_ms() {
  local h o
  h=${ZSHRUN_HOME:-$(_zsh_sandbox)} || return 1
  _zsh_login "$h" true >/dev/null 2>&1   # warm the caches
  # The environment of _zsh_login, spelled out: /usr/bin/time needs a
  # program, not a shell function.
  o=$( { /usr/bin/time -p env -u LC_ALL -u TERM_PROGRAM -u DOTFILES_TERM_HOST \
           HOME="$h" ZDOTDIR="$h" XDG_CACHE_HOME="$h/.cache" PATH="$h/.stubs:$PATH" \
           DOTFILES_TERM_HOST="${ZSHRUN_TERM_HOST-rich}" \
           zsh -l -i -c true </dev/null; } 2>&1 >/dev/null )
  printf '%s\n' "$o" | awk '/^(user|sys)/ {s += $2} END {printf "%d", s * 1000}'
}

# atuin - shell history in SQLite: searchable, deduplicated, and not capped at
# SAVEHIST. Replaces nothing; ctrl-R goes to atuin, Up stays on prezto's
# history-substring-search.
#
# Sourced from .zshrc, after prezto and after .fzf. Prezto's editor module runs
# `bindkey -d`, so anything bound earlier is discarded, and `fzf --zsh` binds
# ctrl-R to its own history widget, so atuin has to come second to take that
# key (2026-09-21 tooling research, section 2).
#
# What loads depends on the host (system/.term_host):
#   rich  everything but the up-arrow binding.
#   warp  the recording hooks alone, so commands typed in Warp reach the same
#         history as every other terminal. No bindings: ctrl-R and ? stay with
#         Warp, whose docs list custom key bindings as a source of broken
#         input. --disable-ai is what removes the ? binding.
#   dumb  nothing: a `zsh -c` shell runs no precmd or preexec to record.
if (( $+commands[atuin] )); then
  case "$DOTFILES_TERM_HOST" in
    dumb) ;;
    warp) eval "$(atuin init zsh --disable-up-arrow --disable-ctrl-r --disable-ai 2>/dev/null)" ;;
    *) eval "$(atuin init zsh --disable-up-arrow 2>/dev/null)" ;;
  esac
fi

cpu_ms() { # cpu_ms [NAME=value...] -- best of 5 warm runs, user+sys ms, real $HOME, on a pty
  local i best= ms
  for i in 0 1 2 3 4 5; do
    ms=$( { /usr/bin/time -p /usr/bin/script -q /dev/null env "$@" zsh -l -i -c true </dev/null >/dev/null; } 2>&1 |
          awk '/^(user|sys)/ {s += $2} END {printf "%d", s * 1000}' )
    [ "$i" -eq 0 ] && continue
    if [ -z "$best" ] || [ "$ms" -lt "$best" ]; then best=$ms; fi
  done
  printf '%s\n' "$best"
}
nt_ms() { # the same, no terminal: what an agent's shell costs
