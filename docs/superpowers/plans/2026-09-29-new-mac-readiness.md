# New Mac readiness (macOS 27) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A clean Apple-silicon Mac on macOS 27.0.1 can be bootstrapped from this repo with no failures, no silent failures, and no regression of the settings the owner uses today — and the shell is measurably faster.

**Architecture:** Four independent workstreams with disjoint file ownership (install flow; Claude + Codex layer; shell performance; macOS defaults, packages and captured configs), then an integration pass by the controller.

**Tech stack:** bash 3.2 (installers, tests), zsh 5.9 (login path), GNU Stow, Homebrew 7, mise 2026.9, Starship 1.26, Prezto.

**Evidence:** six read-only audits dated 2026-09-29 (install-flow trace in a sandbox, macOS 27 research, package validation, live-settings diff, uncaptured-state survey, performance profiling). The controller holds them; each task below carries the findings it needs, with exact values.

## Global Constraints

- **Read `AGENTS.md` first.** bash 3.2 only: no `mapfile`/`readarray`, no `declare -A`, no `declare -n`, no `${x,,}`/`${x^^}`, never `((x++))` under `set -e` (use `x=$((x + 1))`).
- **GNU tools are interactive-only.** Scripts run as `bash script.sh`, hooks, launchd and `xargs`/`find -exec` get BSD tools. No `sed -i` without a suffix argument, no `grep -P`, no `find -printf`, no `stat -c`, no `readlink -f`, no `date --date`, no bare `timeout`. `/usr/bin/sort -V` exists and is allowed.
- **Public repo.** No names, hostnames, emails, computer names, private SSH host aliases, IP addresses or absolute `/Users/…` paths in tracked files. Private values go in gitignored files.
- **Apple silicon only**, `HOMEBREW_PREFIX=/opt/homebrew`.
- **Tests are hermetic.** Never touch the real `$HOME`, `/etc`, the login keychain, `defaults` domains, launchd, Homebrew or mise state. Use `tests/lib.sh` (`sandbox`, `code_of`, `t`, `section`, `finish`) and stub binaries on a sandbox PATH that log their argv. Prefer behavioural tests (run the code against stubs, assert on argv/exit/output). A grep assertion reads `code_of <file>`, never the raw file, and never `! <writer> | grep -q` (use `[ "$(… | grep -c …)" -eq 0 ]`). Mutation-check every new assertion: break the code, watch the test fail, restore it.
- **TDD.** Write the failing test first, watch it fail for the right reason, then the minimal code.
- **Do not run** `dotfiles install|configure|link|unlink|update|clean|setup`, `scripts/install_claude.sh`, `stow`, `launchctl`, `sudo`, `brew install|bundle|tap|trust|uninstall`, `mise install|use|lock` against the real machine. Sandboxed runs with stubs or a sandbox `HOME`/`MISE_*_DIR` are fine.
- **Before every commit:** `bash tests/run.sh` and `./bin/dotfiles test` pass; `shellcheck -e SC1090,SC1091,SC2034,SC2119,SC2154 -s bash <changed bash files>` is clean; `zsh -n` on changed zsh files. Do not push.
- **Commits:** conventional style used in this repo (`fix(install): …`, `perf(shell): …`), small and focused, each ending with the session's attribution trailer lines the controller gives you.
- **Environment traps (the Bash tool's shell is the owner's interactive zsh):** `noclobber` is on, so overwrite with `>|`; `rm`, `cp`, `mv` are aliased to interactive variants and `cat` to `bat`, so use `command rm -f`, `command cp`, `command mv`, `command cat`; Safety Net blocks `git checkout` and `rm -rf` outside the working directory, so use `git switch` and `git show HEAD:<path> >| <path>`.
- **Docs:** each task updates the `docs/agents/*.md` pages and README passages that describe the behaviour it changes. `docs/plans/archive/` is historical: do not edit it.
